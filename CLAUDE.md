# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A cross-platform (Windows, macOS, Linux) desktop GUI app built with PyQt6 (including QtMultimedia, with the bundled FFmpeg backend, and QtSvg), plus `mutagen` for reading audio tags and `keyring` for the Basic-Auth password. Managed with `uv` (build backend `uv_build`, src layout, package `teddycloud_desktop`). Supports Python >= 3.11 (CI tests 3.11 and 3.14); `.python-version` pins 3.14 for development, so don't use stdlib APIs newer than 3.11. Open source under GPL-3.0-or-later (required by PyQt6); `NOTICE` lists third-party attributions.

## Commands

```bash
uv sync                          # create .venv and install dependencies
uv run teddycloud-desktop        # launch the app (console script -> teddycloud_desktop:main)
uv run python -m teddycloud_desktop  # alternative way to launch
uv run pytest                    # tests (tests/, Qt-free logic; conftest sets QT_QPA_PLATFORM=offscreen)
uv run ruff check                # lint
uv run ruff format               # format (line length 130)
uv run --with pyinstaller python packaging/build.py  # standalone build + archive in dist/
uv add <package>                 # add a runtime dependency
uv add --dev <package>           # add a dev dependency
```

GitHub Actions: `.github/workflows/ci.yml` runs ruff and pytest on Linux/Windows/macOS; `release.yml` builds PyInstaller archives on a `v*` tag and attaches them to the GitHub release; its description comes from `packaging/release_notes.py` (the tag's section in `CHANGELOG.md` plus fixed download notes; fails if the section is missing or the tag differs from the `pyproject.toml` version). Every version bump therefore needs a `CHANGELOG.md` section, which `tests/test_release_notes.py` also checks. Don't import the `packaging/` scripts as a package: the name clashes with the PyPI `packaging` module. `packaging/launcher.py` exists because PyInstaller cannot start the package's relative-import `__main__.py` directly. On macOS the `.app` is zipped with `ditto`, because `shutil.make_archive` drops the Qt framework symlinks.

## Architecture

The app is a desktop rebuild of the `/web/tonies` and `/web/tonieboxes` pages of the TeddyCloud web UI (repo `toniebox-reverse-engineering/teddycloud_web`). The relevant web UI code lives in `src/components/tonies/toniecard/` and `tonieslist/`, and in `src/components/tonieboxes/tonieboxcard/` together with `src/data/SettingsDataHandler.ts`. When adding behaviour, check how the web UI does it first and mirror its API calls and flows. `README.md` (English) and `README.de.md` (German, the more detailed one) have the user docs, the full endpoint list, and the web UI features that were deliberately left out.

- `main.py`: `MainWindow` builds the menus (Datei/Tonies/Tonieboxen/Bearbeiten/Ansicht/Hilfe). A `QStackedWidget` holds the welcome label and the pages `ToniesPage`, `TonieboxesPage`, `EncoderPage`, `CustomModelsPage` and `TapPage`, with the `AudioPlayerBar` below it. Each page has a `load()` method; F5 and a settings change call it on the current page. The window owns the shared `TeddyCloudClient`, `ImageCache` and `AppSettings` and passes them in.
- `teddycloud.py`: frozen dataclasses (`TonieCard`, `TonieInfo`, `Toniebox`, `LibraryEntry`) and pure parsers, plus `TeddyCloudClient`. Every client method is async and callback-based: `on_success(result)` and an optional `on_error(message)`. Without `on_error`, the failure goes to the `requestFailed` signal, which the main window shows as a dialog. `TonieCard.raw` keeps the original JSON for the "full" export.
- Auth: `_request()` adds the Basic Auth header only for URLs on the endpoint's own host, so external picture CDNs never get it. `media_url()` puts the credentials into the URL instead, because `QMediaPlayer` cannot set headers.
- `tonies_page.py`: owns all state (cards, filter, selection set, page, overlay, last played) and all actions. `load()` chains several requests: boxes → `core.contentdir` per box → grouped overlay combo → `getTagIndex`. After every change it calls `refresh_card(ruid)` (`getTagInfo`) instead of reloading the whole list. Card widgets are rebuilt for the current page only.
- `tonie_card.py` (tile widget) and `tonie_dialogs.py` (info, edit, library picker) only emit signals or call the client. `EditTonieDialog._run_save_steps` reproduces the web UI's save order (source → nocloud → live → tonie_model).
- `tonies_filter.py` and `export.py` are Qt-free apart from image encoding, so they are easy to test.
- `tonieboxes_page.py` builds one `TonieboxCardWidget` per box from `/api/getBoxes`. As in the web UI, each card fetches its own status settings with the box ID as `overlay`, and also the tag index to resolve the last played tonie. Clicking that tonie emits `showTonieRequested`, which `MainWindow.show_tonie` → `ToniesPage.show_tonie` handle.
- `toniebox_dialogs.py`: `TonieboxSettingsDialog` mirrors `SettingsDataHandler`. Each `_SettingRow` tracks its value and its "überschrieben" (overlayed) state. On save, unchecking overlayed becomes `/api/settings/reset/<key>`. `BOX_SETTING_PREFIXES` is copied from the web UI's `Settings.tsx`. Every settings write is followed by `trigger_write_config()`.
- `encoder_page.py` mirrors the web UI's "server-side encoding" (`components/tonies/encoder/hooks/useEncoder.ts`). `PcmDecoder` uses `QAudioDecoder` with a requested 48 kHz / 2 ch / Int16 format, and the FFmpeg backend resamples. It writes each file to a temp `.pcm` file. `client.upload_pcm` streams those files as multipart parts (one part = one chapter) to `/api/pcmUpload` with no transfer timeout. `.taf` inputs are decoded from a temp copy without the 4096-byte header, because a seeked `QIODevice` does not work with the FFmpeg backend. Browser-side WASM encoding (`/api/tafUpload`) is intentionally not implemented.
- Custom models (`custom_models*.py`, web UI: `components/tonies/custommodel/`). `custom_models.py` is Qt-free and holds `CustomEntry`, normalization (`entry_from_api` / `clean_entry` / `to_payload` mirror `normalizeEntryFromApi` / `toEntry`; empty fields are omitted from the payload), list validation, filter and sort. The page only keeps the persisted list. Edits live in the reused `CustomModelEditDialog` until saved. Save order: field errors → `validate_entries` → if the model ID changed, `confirm_rename` + `/api/toniesCustomJsonRename` → `/api/toniesCustomJsonUpsert`. `client.post_json` passes the HTTP 4xx body text through as the error message. `LibraryAudioIndex` scans the library once (throttled) to map audio_id+hash to `lib://` paths; it is display-only.
- `encoder_custom.py` is the encoder's optional "Custom-Tonie anlegen" box (this is not in the web UI). The draft is validated before encoding. `EncoderPage` creates the audio ID itself (`self._audio_id` from `new_audio_id()`, which is the web UI's time-based ID but strictly increasing within the process, so two encodes in the same second never share an ID) so that after `/api/pcmUpload` it can find the server-computed SHA-1 hash in the target folder's file index (`find_taf_hash`, matching on name and audio ID), then upsert the model. "Weitere Angaben" reuses `CustomModelEditDialog` with `show_audio=False`; its save only returns the draft. `MetadataFinder` reads cover art, artist and album through `audio_tags.read_audio_tags` (mutagen, Qt-free). It handles ID3, Vorbis comments incl. `METADATA_BLOCK_PICTURE` (FLAC/OGG Vorbis/Opus), MP4 and ASF (WMA), plus a small RIFF-INFO fallback for WAV, which mutagen does not read. The album artist is preferred over track artists. It reads one file per event-loop pass and drops stale searches through a generation counter. Do not go back to `QMediaPlayer` metadata: Qt only sees container-level tags, so OGG/Opus tags are invisible there. Series and episode are filled through `_set_auto_series` / `_set_auto_episode`, which only replace a field that is empty or still holds the last automatic value. Before the upsert, the cover is scaled down and uploaded to the root of `custom_img` (`/api/fileUpload` cannot create folders) as `<model>.jpg`, and `pic` is set. A failed image upload does not block creating the model.
- TeddyAudio Playlists (`tap.py`, `tap_page.py`; web UI: `pages/tonies/TeddyAudioPlaylistsPage.tsx`, `filebrowser/hooks/useTAPEditor.ts`, `filebrowser/modals/TeddyAudioPlaylistEditorModal.tsx`; server: `src/tonie_audio_playlist.c`). A `.tap` is JSON `{type: "tap", audio_id, filepath: "lib://….taf", name, files: [{filepath, name}]}` in the library. Load it via `GET /library/<path>` and save it via `client.upload_library_file` (`/api/fileUpload`, file name `safe_tap_name(name) + ".tap"`) into the folder being browsed. The server builds the TAF from `files` with FFmpeg on first play and rebuilds it when the TAF's audio ID differs from `audio_id`. `AssignTonieDialog` mirrors `useAssignSourceToTonie` (source → nocloud → live). `LibraryFileDialog` takes `extensions` and `max_files` (multi-select) for the editor. `tap_convert.TapConverter` builds the TAF in the GUI instead of the server's FFmpeg path: download each source (`client.download_to_file`), decode with `PcmDecoder`, create missing folders, call `upload_pcm` to the TAP's `filepath` (this overwrites an existing TAF), verify with `find_taf_hash`, then write the new audio ID back into the same `.tap`. A valid TAF at `filepath` makes the server treat the TAP as `CT_SOURCE_TAP_CACHED` and serve it directly. Every run gets a fresh `new_audio_id()` so boxes re-download.
- Never drive a **modal** `QProgressDialog` from network progress signals. Its `setValue()` calls `processEvents()`, and that re-entrancy breaks a streaming `QHttpMultiPart` upload (it truncates and hangs). Use a non-modal dialog parented to the main window, and disable the page instead. Note that `QProgressDialog.cancel()` called in code does not emit `canceled`; only the button or closing the dialog does.
- `languages.py` is generated from `languageOptions` in the web UI's `LanguageFlagIcon.tsx`.
- Multipart uploads must go through `TeddyCloudClient._post_multipart`. Qt quotes the boundary (`boundary="…"`), but TeddyCloud's HTTP server (CycloneTCP, `http_server_misc.c`) keeps the quotes as part of the boundary. `multipart_handle` in `server_helpers.c` then spins forever without reading the body, so the upload stalls with no error at all. `_post_multipart` sets the `Content-Type` header with an unquoted boundary. Python's multipart parsers accept the quoted form, so a fake test server must parse the boundary as literally as CycloneTCP does, or this bug goes unnoticed.
- `QNetworkRequest.setTransferTimeout` already starts counting while a request waits in Qt's queue, which allows at most 6 connections per host. A burst of requests (for example all pictures of a page) therefore times out ("Operation timed out") against a slow TeddyCloud before most of the requests are even sent. `ImageCache` keeps its own queue with at most `MAX_PARALLEL_DOWNLOADS` running and retries once. Any future bulk loading should be throttled the same way.
- Errors from `TeddyCloudClient._fail` and the encoder steps are logged through `logging.getLogger("teddycloud_desktop")`. `main()` configures INFO-level console output.
- `settings.py`: `AppSettings` stores everything in `QSettings("teddycloud-desktop", "teddycloud-desktop")` except the password, which goes to the OS keyring (service `teddycloud-desktop`, account `basic-auth`). If the keyring raises (no backend, D-Bus error), it falls back to plaintext QSettings, sets `keyring_available = False`, and the settings dialog shows a hint. A plaintext password found in QSettings is moved into the keyring on load.
- `client.set_setting` treats a body of `ERROR` as a failure, because TeddyCloud answers HTTP 200 even when it rejects a value.

TeddyCloud API facts, verified against `src/handler_api.c` in the teddycloud repo:
- "List all Tonies" uses `/api/getTagIndex`. Like the web UI, the page shows only `type == "tag"` entries with `hide == false`.
- `/api/toniesJsonSearch` (`searchModel`/`searchSeries`/`searchEpisode`) only searches the tonies.json catalog. It returns at most 18 results and an empty list when no term is given, so it cannot be used to list all Tonies. Its only use here is model search and validation in the edit dialog.
- `POST /content/json/set/<ruid>` takes a `text/plain` body like `live=true` or `source=<urlencoded>`. Accepted keys: `source`, `tonie_model`, `live`, `nocloud`, `hide`, `claimed`.
- Seeking to a track position needs HTTP Range support, which TeddyCloud has. Python's `http.server` does not, so test servers must implement it.

You can test without a real TeddyCloud: run a local HTTP server that serves sample JSON for these endpoints, then drive `MainWindow` from a script with `QT_QPA_PLATFORM=offscreen`, using `QEventLoop` + `QTimer` waits and `widget.grab().save(...)` for screenshots. Patch `QMessageBox.warning/question` and `QFileDialog.getSaveFileName` so nothing blocks.
